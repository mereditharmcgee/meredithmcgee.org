## Directory Purposes

**src/:**
- Purpose: All application source code
- Contains: Pages, components, content, styles, configuration
- Key files: `consts.ts`, `content.config.ts`

**src/assets/:**
- Purpose: Optimized image assets
- Contains: Blog placeholder images used as fallbacks
- Key files: `blog-placeholder-1.jpg` (default blog hero image)

**src/components/:**
- Purpose: Reusable Astro components for composition
- Contains: Header, Footer, BaseHead, interactive components
- Key files: `BaseHead.astro`, `Header.astro`, `Footer.astro`, `ThreeAudiences.astro`

**src/content/:**
- Purpose: Markdown-based content with schema validation
- Contains: Two collections: blog and portfolio
- Structure: Frontmatter (YAML) + content (markdown)

**src/content/blog/:**
- Purpose: Blog post content
- Contains: 5 blog posts (first-post.md, second-post.md, third-post.md, using-mdx.mdx, markdown-style-guide.md)
- Schema: `title`, `description`, `pubDate`, `updatedDate` (optional), `heroImage` (optional)

**src/content/portfolio/:**
- Purpose: Portfolio project showcase entries
- Contains: 9 portfolio items documenting public health projects
- Schema: `title`, `category`, `image`, `description`, `tags`, `size`, `order`, plus optional metadata (`role`, `challenge`, `impact`, `skills`, `timeline`, `organization`, `video`)

**src/layouts/:**
- Purpose: Layout templates applied to content pages
- Contains: Single layout `BlogPost.astro`
- Usage: Wraps blog content with styling, meta tags, date formatting

**src/pages/:**
- Purpose: File-based route definitions
- Contains: Static pages, dynamic routes, RSS feed generation
- Routing: Astro converts filenames to URL routes

**src/pages/blog/:**
- Purpose: Blog content routes
- Files:
  - `index.astro` - Blog listing page
  - `[...slug].astro` - Dynamic blog post pages

**src/pages/portfolio/:**
- Purpose: Portfolio content routes
- Files:
  - (no index - portfolio list at `/portfolio` from `src/pages/portfolio.astro`)
  - `[slug].astro` - Dynamic portfolio project pages

**src/styles/:**
- Purpose: Global CSS and design system
- Contains: Single file `global.css` with all shared styles
- Includes: CSS variables, typography scales, button styles, layout utilities, responsive breakpoints

**public/:**
- Purpose: Static files served directly without processing
- Contains: Images, fonts, favicon (all images referenced in content and HTML)
- Served as: Exact paths `/hero-image.jpg`, `/logo-m.png`, etc.

**dist/:**
- Purpose: Production build output (generated at build time)
- Contains: Static HTML files, CSS, optimized images
- Committed: No (git ignored)
- Generated by: `npm run build`

**.astro/:**
- Purpose: Astro build cache and generated type definitions
- Contains: Cached build artifacts, TypeScript type stubs
- Committed: No (git ignored)
- Generated by: Astro build system

## Naming Conventions

**Files:**
- Astro components: PascalCase (e.g., `BaseHead.astro`, `Header.astro`)
- Content files: kebab-case (e.g., `first-post.md`, `bradbury-sullivan-grants.md`)
- Styles: lowercase with hyphens (e.g., `global.css`)
- Pages: lowercase with hyphens (e.g., `[...slug].astro`, `index.astro`)
- Config files: camelCase with extensions (e.g., `astro.config.mjs`, `tsconfig.json`)

**Directories:**
- src subdirs: lowercase (components, layouts, pages, styles, content, assets)
- Content collections: plural, matching Zod collection name (blog, portfolio)
- Generated dirs: prefixed with dot (.astro, .planning, .vscode)

**CSS Classes:**
- kebab-case (e.g., `.hero-section`, `.portfolio-grid`, `.mobile-menu-toggle`)
- BEM modifier style sometimes used: `.btn--small`, `.btn-small` (both patterns present)
- Semantic classes for elements: `.container`, `.card`, `.button`

**Variables:**
- CSS custom properties: `--color-dark`, `--color-gold`, `--box-shadow`
- TypeScript: camelCase for variables and functions
- Astro props: camelCase (e.g., `heroImage`, `pubDate`)

**Routes:**
- lowercase with hyphens: `/my-work`, `/portfolio`, `/blog`
- Dynamic segments: `[slug]` (single item), `[...slug]` (blog with dates)

## Where to Add New Code

**New Blog Post:**
1. Create file in `src/content/blog/{kebab-case-title}.md` or `.mdx`
2. Add frontmatter matching schema in `src/content.config.ts`:
   ```yaml
   ---
   title: "Post Title"
   description: "Short description"
   pubDate: 2026-02-28
   updatedDate: 2026-02-28 (optional)
   heroImage: image path (optional)
   ---
   # Content starts here...
   ```
3. Build and run: `npm run build` or `npm run dev`
4. Post auto-appears in `/blog` listing and at `/blog/{id}`

**New Portfolio Project:**
1. Create file in `src/content/portfolio/{kebab-case-title}.md`
2. Add frontmatter matching schema in `src/content.config.ts`:
   ```yaml
   ---
   title: "Project Title"
   category: "Category Name"
   image: "/image-path.jpg"
   description: "Description"
   tags: [tag1, tag2]
   size: small/medium/large
   order: 10
   role: "My Role" (optional)
   challenge: "Challenge" (optional)
   impact: "Impact" (optional)
   skills: [skill1, skill2] (optional)
   timeline: "Timeline" (optional)
   organization: "Organization" (optional)
   video: "/video.mp4" (optional)
   ---
   # Content...
   ```
3. Project auto-appears in `/portfolio` grid at correct order, filterable by tags

**New Page:**
1. Create file in `src/pages/{route-name}.astro`
2. Template:
   ```astro
   ---
   import BaseHead from '../components/BaseHead.astro';
   import Header from '../components/Header.astro';
   import Footer from '../components/Footer.astro';
   import { SITE_TITLE } from '../consts';
   ---

   <html lang="en">
     <head>
       <BaseHead title={`Page Title | ${SITE_TITLE}`} description="Description" />
     </head>
     <body>
       <Header />
       <!-- Your content -->
       <Footer />
     </body>
   </html>
   ```
3. Automatically accessible at `/route-name`

**New Component:**
1. Create file in `src/components/{PascalCase}.astro`
2. Include scoped `<style>` block
3. Import in pages as: `import {PascalCase} from '../components/{PascalCase}.astro';`
4. Use as: `<PascalCase propName={value} />`

**Shared Styles:**
- Add CSS rules to `src/styles/global.css`
- Use existing CSS variables: `var(--color-dark)`, `var(--color-gold)`, etc.
- Follow responsive pattern: mobile-first, `@media (max-width: 768px)` breakpoint

**Utilities/Helpers:**
- Create `.ts` file in `src/` root or subdirectory
- Export functions/constants from `src/consts.ts` for site-wide constants

## Special Directories

**src/assets/:**
- Purpose: Optimized image assets
- Generated: No (manually added)
- Committed: Yes
- Processed by Astro's image optimization pipeline

**dist/:**
- Purpose: Production build artifacts
- Generated: Yes (by `npm run build`)
- Committed: No (git ignored)
- Contains: Static HTML, CSS, optimized images

**.astro/:**
- Purpose: Astro build cache and type definitions
- Generated: Yes (by Astro)
- Committed: No (git ignored)
- Deletable: Safe to delete; regenerated on next build

**.planning/:**
- Purpose: GSD planning documents
- Generated: No (created manually or by GSD tools)
- Committed: Yes
- Contains: ARCHITECTURE.md, STRUCTURE.md, etc.
